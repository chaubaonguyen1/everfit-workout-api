## M0 — Setup
- 2026-10-14 · Plan review: first folder-structure proposal from the AI had no dedicated place for
  reusable helpers (only `common/pagination`, `common/validators`). Reviewer asked for a
  "custom hook"-like layer. Refined into `common/utils` (pure), `common/helpers` (infra-aware),
  `common/decorators` + `common/pipes` (request-level reuse), plus a placement rule
  ("used by ≥ 2 modules → common/"). Enforced purity of `utils/` and `domain/` via ESLint
  `no-restricted-imports`.
- 2026-10-14 · Scaffold: AI initially pinned NestJS 10 from memory. `npm install @nestjs/swagger`
  failed (latest needs Nest 12). Checked the registry: Nest 12 is ESM-only (`"type": "module"`),
  which makes Jest/ts-jest painful. **Decision:** Nest 11 (latest CommonJS line, supported by
  nestjs-pino 5 / swagger 11 / config 4); TypeScript 5 rather than the brand-new TS 7; Prisma 6
  rather than the Prisma 8 RC. Lesson: verify versions against the registry, not training data.

## M1 — Foundation
- 2026-10-14 · **AI bug caught by e2e, missed by unit tests.** AI's exception filter detected
  malformed JSON via body-parser's `err.type === 'entity.parse.failed'`. The unit test (hand-made
  error object) passed, but the real e2e returned `VALIDATION_ERROR`. Debugged by temporarily
  logging the exception in the filter → it was a `BadRequestException`. Root cause in
  `@nestjs/core/router/routes-resolver.js` `mapExternalException`: Nest converts every
  `SyntaxError` into `BadRequestException(message)` and drops `type`. Fix: an Express error
  middleware right after the JSON parser translates body-parser errors into `DomainError`
  before Nest wraps them. Lesson: mocks encode the AI's assumptions; test against the real stack.
- 2026-10-14 · **Second-order bug found in manual docker smoke test:** the MALFORMED_JSON response
  had no `requestId`. Request ids were generated by pino-http, which Nest registers as module
  middleware *after* the body parser. Moved id generation into a first-in-chain Express middleware
  (`requestIdMiddleware`); pino now reuses `req.id`. Added an e2e assertion so it can't regress.
- 2026-10-14 · Rejected: AI's plan had a `RequestIdInterceptor`. Interceptors run after guards and
  pipes and never see body-parser errors, so the id would be missing exactly when debugging
  matters most. Replaced with Express middleware (see above).
- 2026-10-14 · Port 5432 already taken on the dev machine by a local Postgres → compose maps
  the dev DB to host port 5434 (test DB 5433).

## M2 — Data layer
- 2026-10-14 · **Rejected my own plan item:** the plan stored `volume_kg` / `e1rm_kg` as Postgres
  `GENERATED ALWAYS` columns. Prisma cannot model generated columns, so `prisma migrate dev` would

  duplicates the Epley formula in SQL and TS. Switched to computing metrics in
  `workouts/domain/set-metrics.ts` at write time (single, unit-tested source of truth) and storing
  them as ordinary columns. Verified no drift with an empty `migrate dev --create-only`.
- 2026-10-14 · Prisma generated `muscle_groups TEXT[]` as **nullable** although the Prisma type is
  non-null `String[]` → added `SET NOT NULL` in the hand-written part of the migration, together
  with CHECK constraints (reps > 0, weights >= 0) that Prisma cannot express.
- 2026-10-14 · PR indexes include `performed_at` after the metric (`weight_kg DESC, performed_at`)
  so "first time this record was achieved" is answered from one index entry (tie-break).
- 2026-10-14 · Catalog sync: also clears muscle groups for exercises removed from the config,
  otherwise "configurable" would only ever add mappings, never remove them.

## M3 — Bulk workout logging
- 2026-10-14 · Time zones: chose `Intl`-based conversion over adding a date library; correctness
  pinned by DST tests (New York summer/winter, right after spring-forward) and by rejecting
  impossible dates that `Date` silently rolls over (`2026-02-30` → March 2).
- 2026-10-14 · Idempotency design: claim the key with `INSERT … ON CONFLICT DO NOTHING` *inside*
  the write transaction. A concurrent duplicate blocks on the uncommitted key row until the
  first commits, then replays its stored response. Rejected alternative: insert the key at the
  end and catch P2002 — simpler, but every concurrent duplicate would do the full write first.
- 2026-10-14 · Deadlock avoidance: exercises in a batch are created in sorted order, so two
  concurrent batches introducing the same new exercises lock rows in the same order.
- 2026-10-14 · Kept services Prisma-free with a `TransactionRunner` (unit of work + retry on
  P2034) instead of calling `prisma.$transaction` from the service, per the layering rule.
- 2026-10-14 · Test isolation (reviewer m10): each e2e test uses a fresh userId instead of
  truncating tables — suites stay independent without cleanup-order coupling.

## Review of M3 by the reviewer agent (`docs/reviews/m3-review.md`)
- **Real bug in my code, confirmed before fixing:** DST-gap handling in `zonedWallTimeToUtc`.
  A date-only `2026-09-06` in `America/Santiago` (clocks skip midnight) was stored as 23:00 on
  Sep 5 local — the entry moved to the previous day. My DST tests only covered times *after* a
  transition, never *inside* the gap. Reproduced with the built code first, then fixed with
  "compatible" disambiguation (gap → forward, overlap → earlier) and added a full-year property
  test (date-only never changes local day in 4 DST zones).
- **Accepted:** name length checked after NFKC normalization (`'ﷺ'` expands to 18 chars) + map
  P2000; map P2028 (tx timeout while waiting on a held key) to 503; warn-log DB errors mapped
  to 4xx; TransactionRunner retry unit tests; stronger e2e (lb stored at full precision,
  4 of 5 concurrent duplicates are replays); schema comment no longer promises a TTL job.
- **Reviewer was right that my concurrency test proved less than its name:** it also passed if
  requests ran sequentially. Added a deterministic test that holds an uncommitted claim in an
  open transaction and asserts the HTTP request blocks until rollback.
- **Rejected (after checking):** canonicalizing stored time zones via
  `resolvedOptions().timeZone`. Node's ICU returns legacy CLDR ids
  (`Asia/Ho_Chi_Minh` → `Asia/Saigon`, `Asia/Kolkata` → `Asia/Calcutta`), so clients would get
  back a different name than they sent. Kept their spelling; only bounded the formatter cache.
- **Rejected:** injecting a Clock — `prepareEntries` already takes `now`, so the only
  time-dependent logic is pure and tested deterministically.
- **To document in README:** time-zone rules (offset in `date` wins; `timezone` applies to
  dates without offset and is stored as sent), replay returns 201 + `Idempotent-Replayed`,
  global exercise table (first logger sets the display name).
